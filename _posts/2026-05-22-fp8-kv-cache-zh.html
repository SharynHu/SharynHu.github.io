核心想法很简单：不要把 KV cache tensor 存成 FP16/BF16（每个值 2 bytes），而是把它们量化到 FP8（每个值 1 byte），这样原始 KV cache memory 大约可以减半。

一个有用的估算公式是：

\[ \begin{aligned} \text{KV cache size} \approx {} & 2 \times \text{num layers} \times \text{batch size} \times \text{sequence length} \\ & \times \text{KV heads} \times \text{head dimension} \times \text{bytes per element} \end{aligned} \]
  • FP16/BF16 每个值占 2 bytes。
  • FP8 每个值占 1 byte，所以在不考虑 scale/metadata overhead 之前，同样的 memory budget 大约可以存下 2× 的 KV values。

Floating Point 的表示方式

一个 floating point number 在二进制里由 3 个字段表示：

在 binary floating point 里：

  • sign → 表示正数或负数
  • exponent → floating-point value 内部的 power-of-two scale
  • mantissa → 实际有效数字，也就是 precision

如何从 bit representation 还原 FP number

对 normalized finite values，简化公式是：

\[ \text{value} = (-1)^{\text{sign}} \times 2^{(\text{exponent} - \text{bias})} \times 1.\text{mantissa} \]

这个公式不覆盖 zero、subnormal values、infinities 或 NaNs。这些值由特殊的 exponent patterns 处理。

我们来 decode 这个 FP32 bit pattern：0 | 10000001 | 10100000000000000000000

  • Sign: (-1)^0 = +1 → positive
  • Exponent
    • 10000001 的二进制值等于十进制 129
    • FP32 的 bias = 127
    • exponent = 2(129-127) = 4
  • Mantissa:
    存储的 bits 是 10100000000000000000000。读取时，把它们当成 implied 1. 后面的 binary fraction digits：
1.10100000000000000000000
  ↑↑
  bit1 = 1 → contributes 1 × 2^(-1) = 0.5
  bit2 = 0 → contributes 0 × 2^(-2) = 0
  bit3 = 1 → contributes 1 × 2^(-3) = 0.125
  rest are 0

1 + 0.5 + 0 + 0.125 = 1.625
  • 全部相乘： (+1) × 4 × 1.625 = 6.5 ✓

如何用 FP32 表示一个数

如果要表示数字 -6.5：

  • sign: 负数 → sign bit = 1
  • 把 6.5 写成 binary: 6.5 = 110.1 in binary
  • normalize:（像科学计数法一样移动小数点，直到小数点前只剩一位）：110.1 → 1.101 × 2^2
  • 存储 exponent
    FP32 使用 bias of 127，所以 exponent field 里存的是 2 + 127 = 129 = 10000001。bias 的作用是：不用给 exponent 单独加一个 sign bit，也能表示 negative exponents。
  • 存储 mantissa:
    对 normalized values，开头的 1. 是 implied，所以只存小数点后面的部分：101，后面补 0 填满 23 bits：10100000000000000000000
  • 最终存储的 bits: 1|10000001|10100000000000000000000

FP8 到底是什么

在讨论 FP8 之前，先把 convention 讲清楚。

在这篇 note 里，E4M3 和 E5M2 首先表示 bit allocation：

  • E4M3 — 1 sign bit, 4 exponent bits, 3 mantissa bits
  • E5M2 — 1 sign bit, 5 exponent bits, 2 mantissa bits

只有 bit allocation 并不等于完整的 FP8 dtype definition。 在 bit widths 固定之后，FP8 到底能表示哪些数字，还取决于：

  • exponent bias：移动 exponent window，因此会改变最大/最小 range
  • reserved special patterns：最高位的 exponent/mantissa codes 是表示 finite numbers、NaN，还是 infinity
  • zero/subnormal rules：是否存在 negative zero，以及接近 0 的 tiny values 如何编码
  • rounding and overflow policy：real values 被转换成 FP8 storage 时如何处理

这些规则定义的是 FP8 number 本身。它们和后面把 FP16/BF16 tensors 映射到 FP8 cache storage 时用到的 external quantization scale 不是同一个东西。

所以，除非指定 exact dtype/standard，否则 E4M3 更像是一个 family name。

几个例子：

  • OCP / ONNX E4M3FN / NVIDIA Transformer Engine E4M3：finite-only E4M3，通常 max finite value 大约是 ±448。
  • ONNX E4M3FNUZ-style variants：finite-only，没有 negative zero，bias 不同，max finite value 大约是 ±240。
  • E5M2：exponent range 更大，max finite value 大约是 ±57344，但只有 2 mantissa bits。

对 KV cache 来说，当 calibrated quantization scales 可用时，E4M3 通常更常见，因为它比 E5M2 多保留了 1 个 mantissa bit。对 attention quality 来说，这一点额外 precision 通常比 E5M2 提供的额外 range 更重要。

在这篇 note 里，当我解释 bit layout 时，我讲的是 generic E4M3/E5M2 ideas。当我提到 vLLM/SGLang KV cache behavior 时，我讲的是这些 backends 文档中的 FP8 KV cache implementation，而不是在重新定义 FP8 standard。

感受一下 mantissa bits 变少的影响

假设有一个二进制值 1.0011011，你需要把它存成：

  • FP32（23 mantissa bits）→ 存储 00110110000000000000000 → 几乎精确
  • FP8 E4M3（3 mantissa bits）→ 只能保留 3 个 mantissa bits，所以必须 round 到最近的 representable FP8 value
original:       1.0011011
nearby FP8s:    1.001 or 1.010
stored result:  whichever is chosen by the rounding rule

这就是 quantization error。这个值不是简单地被“截断”；真实实现通常会 round 到附近的 representable value，如果超出 FP8 range，也可能被 saturated/clipped。

每个字段实际控制什么

  • Exponent bits → range
    更多 exponent bits 通常意味着更大的 exponent window，但最终 range 还取决于 bias 和 special-value rules。
FP32: exponent = 8 bits → range up to ~3.4 × 10^38
FP8 E4M3FN / OCP / NVIDIA Transformer Engine style → max around ±448
FP8 E4M3FNUZ-style variants → max around ±240
FP8 E5M2 → max around ±57344

如果值超过 representable range → overflow / saturation / special value，具体取决于 exact format 和 conversion rule。

  • Mantissa bits → precision
    更多 mantissa bits = 更多 significant digits，也就是两个相邻 representable numbers 之间更细的 resolution。
FP32:     23 mantissa bits → ~7 decimal digits of precision
FP16:     10 mantissa bits → ~3 decimal digits of precision
FP8 E4M3: 3 mantissa bits  → much coarser precision

如果值落在两个 representable numbers 中间 → rounding error。

容易混淆的部分：quantization scheme

不能直接 naive 地把 FP16 cast 成 FP8。这里会引入第二个、含义不同的 “scale”：external quantization scale。

完整故事里有两个 scale：

  • internal exponent scale：存在于每一个 FP8 value 内部，来自 2^(exponent - bias)
  • external quantization scale：metadata，用来把 FP16/BF16 tensor values 映射到 FP8 cache storage

重要

这个 quantization scale 不是新的 FP8 standard。FP8 dtype/standard 定义的是一个 8-bit code 如何映射到一个 FP8 number。KV-cache quantization scheme 存储的是 FP8 bytes 加 scale metadata，并在写入/读取 KV cache 时使用这些 metadata。

  • 所以 vLLM/SGLang 并不是通过增加 scale 来重新定义 FP8 bit format。它们是在使用一个 backend FP8 dtype，并把它包装进 KV-cache quantization scheme。
  • 概念上，scale granularity 可以是 per-tensor、per-channel/head、per-token 或 per-block。更细的 granularity 通常精度更好，但会增加 metadata 和 implementation overhead。
  • 对当前 vLLM/SGLang docs 里讨论的 FP8 KV cache implementations，实际情况更严格：它们当前文档说明 FP8 KV cache 使用 per-tensor scalar scaling，更细粒度 scaling 仍然是设计/开发方向，而不是默认行为。

为什么这对 FP8 KV cache 很重要

只有 3 个 mantissa bits 时，相邻 representable values 之间会很远。在 1.x 附近，E4M3 的 spacing 是二进制式的，不是十进制式的：

possible E4M3-like normalized values near 1:
1.000, 1.001, 1.010, 1.011, ...

所以当你把 K 或 V vector value 存成 FP8 时，它会被 round 到附近的 representable value。external quantization scale 会尽量把 tensor values 拉伸到有效使用 FP8 range 的位置，从而同时减少 clipping 和过大的 rounding error。

approximation error 会出现在哪里

KV cache quantization 是 lossy 的。主要担心的是：

  • K vectors 被轻微扭曲 → attention score distribution 发生偏移
  • V vectors 被轻微扭曲 → attention 混合出来的 values 发生变化
  • 误差在很多 layers 和 long contexts 上累积 → output quality 可能下降

实践中，如果 backend、scaling factors 和 model 都合适，FP8 E4M3 KV cache 通常只会带来很小的 accuracy degradation。

但这不是自动成立的：

  • calibrated scales 通常比盲目使用 scale 1.0 更好
  • backend support 很重要，因为 unfused dequantization 可能很慢
  • 影响取决于 model architecture、sequence length 和 quantization format
