MLA (Multi-head Latent Attention) is the attention mechanism introduced by DeepSeek in DeepSeek-V2 and refined in V3. It is designed to solve one specific problem: the KV cache is too big.

The problem MLA solves

For autoregressive inference, every past token's $K$ and $V$ vectors need to be kept in memory so future tokens can attend to them. For a model with $L$ layers, $h$ heads, and head dimension $d_h$:

\[ \text{KV cache per token} = 2 \times L \times h \times d_h \]

The factor of 2 is for $K$ and $V$. For a large model with long context, this dominates GPU memory and memory bandwidth.

Every decoding step has to read the existing KV cache from HBM to compute attention. Larger cache means more HBM traffic, which slows decoding and limits batch size.

Several techniques attack this problem:

  • MQA (Multi-Query Attention): all heads share one $K$ and one $V$. It gives the smallest KV cache, but can lose head-specific capacity.
  • GQA (Grouped-Query Attention): heads are divided into groups, and each group shares $K$ and $V$. It trades more cache than MQA for better quality.
  • MLA: compresses $K$ and $V$ into a learned low-rank latent, then lets each head recover head-specific behavior through learned projections. Its value is small cache with much stronger quality than simple sharing.

The core idea: low-rank joint compression of K and V

Instead of storing $K$ and $V$ per head, MLA stores one small latent vector $c_{kv}$ per token. From that latent, the model can reconstruct head-specific $K$ and $V$ behavior when needed.

  • Standard MHA per token: $K = x \times W_K$, $V = x \times W_V$
    • Total cache per token per layer: $2 \times h \times d_h$
  • MLA per token: $c_{kv} = x \times W_{DKV}$
    • Shape: $(d_c,)$ where $d_c \ll h \times d_h$
    • $K = c_{kv} \times W_{UK}$, shape $(h \times d_h)$, not stored as full cache
    • $V = c_{kv} \times W_{UV}$, shape $(h \times d_h)$, not stored as full cache
    • Cache before adding the decoupled RoPE path: $d_c$; in DeepSeek's final design, cache becomes $d_c + d_h^R$.

$W_{DKV}$ is the down-projection that compresses into the latent. $W_{UK}$ and $W_{UV}$ are up-projections that recover head-specific key/value behavior from that latent.

DeepSeek-V2 uses $d_c = 512$ and a decoupled RoPE key dimension $d_h^R = 64$. The final cached state is $d_c + d_h^R = 576$ elements per token per layer, compared with standard MHA's $2 \times h \times d_h = 32768$ for $h=128, d_h=128$. That is about 57x less KV cache than MHA.

Why this preserves head diversity better than MQA/GQA

MQA forces all heads to share the same $K$ and $V$, and GQA shares them within each group. That reduces cache by reducing head diversity.

MLA is different: the cache is shared, but each head still gets head-specific $K$ and $V$ behavior through learned up-projections from $c_{kv}$.

The latent $c_{kv}$ is a compressed representation that preserves enough information for each head's up-projection to recover its own distinct $K$ and $V$ behavior. The compression is learned jointly with the model, so it captures the information the heads actually need.

Mental model

  • MQA is one shared sauce for every head.
  • MLA is one concentrated stock; each head uses its own learned projection to turn it into the flavor it needs.

The absorption trick: avoid materializing full K/V cache

The clever part is that the full reconstructed keys do not need to be materialized for every cached token during inference.

In standard attention, the score path would look like:

\[ \text{score} = QK^T = xW_Q W_{UK}^T c_{kv}^T \]

Since $W_{UK}$ is fixed, it can be pre-multiplied into the query projection:

\[ W_{Q\_absorbed} = W_Q W_{UK}^T \]
\[ Q' = x W_{Q\_absorbed}, \qquad \text{score} = Q' c_{kv}^T \]

So at inference time, you do not need to materialize full reconstructed $K$ for every cached token. The query-side projection can be arranged so attention scores are computed against the latent cache directly.

The value side is similar in spirit but not identical algebraically: attention first aggregates over the compressed latent cache, then the value-side up-projection is applied before the output projection. The system still uses the learned up-projection weights, but it avoids storing and reading the full per-head $K$/$V$ cache.

Net effect: MLA trades a small amount of projection compute for a much smaller KV cache and much less HBM traffic during decoding.

The RoPE problem and the decoupled design

MLA compresses $K$ and $V$ into a small latent vector $c_{kv}$ per token, dramatically reducing KV cache size. However, $c_{kv}$ only stores content. To get the full content key, the model would reconstruct it via:

\[ K = c_{kv} \times W_{UK} \]

The absorption trick avoids materializing those full reconstructed keys in the attention path by pre-merging $W_{UK}$ into $W_Q$, allowing the model to attend directly to $c_{kv}$ without storing full per-head keys.

But RoPE breaks absorption: RoPE rotates $K$ by a position-dependent matrix $R(j)$ after reconstruction, and each cached token has a different $R(j)$.

\[ K_{rotated} = R(j) \times K \]

The decoupled design solves this by splitting $K$ into two paths:

  • Position-independent content path: large, derived from $c_{kv}$, no RoPE, absorption-friendly.
  • Position-dependent RoPE path: small, stores $K_{rope}$ with position encoding.
Position-independent path:
c_kv    = x * W_DKV      # compressed latent, small, stored in cache
K_nope  = c_kv * W_UK    # content key; not stored as full KV cache at inference

Position-dependent path:
K_rope  = RoPE(x * W_KR) # small extra key vector with RoPE applied

Each token's cache now holds two things: the compressed latent $c_{kv}$ and a shared $K_{rope}$.

\[ \text{score} = Q_{nope}K_{nope} + Q_{rope}K_{rope} \]

The no-RoPE path gets absorbed. The RoPE path is small and shared across heads, so the total cache is still dramatically smaller than standard MHA.

The numbers for DeepSeek-V2

Cached, shared across all heads:

  • $c_{kv}$: one per token, same for every head
  • $K_{rope}$: one per token, same for every head

Per-head, different for each head:

  • $W_{UK}^h$: each head has its own up-projection to reconstruct its own $K_{nope}$ from the shared $c_{kv}$
  • $W_{UV}^h$: each head has its own up-projection to reconstruct its own $V$ from the shared $c_{kv}$

So at attention time for head $h$:

  • $K_{nope}^h = c_{kv} \times W_{UK}^h$
  • $V^h = c_{kv} \times W_{UV}^h$
  • $K_{rope}$ is the same for all heads
  • $\text{score}^h = Q_{nope}^h \times K_{nope}^h + Q_{rope}^h \times K_{rope}$

Different heads see different $K_{nope}$ and $V$, but they all attend to the same $K_{rope}$. This makes sense: $K_{rope}$ only carries position information, while the per-head content relevance lives in the projected latent path.

MLA cache:
  c_kv:    512  (shared, carries content for all heads)
  K_rope:   64  (shared, carries position)
  total:   576  (regardless of number of heads)

MHA cache:
  K + V: 2 * 128 heads * 128 dim = 32768

MQA cache:
  K + V: 2 * 128 dim = 256

GQA cache:
  K + V: 2 * n_g * 128
  MLA is cache-equivalent to GQA with n_g = 576 / 256 = 2.25 groups.

This is the key insight of MLA: head diversity comes from the per-head up-projections, not from the cache. The cache only stores shared representations; the per-head specialization is a compute-time operation, not a storage-time cost.

KV cache per token per layer 2 * h * d_h 2 * d_h 2 * g * d_h d_c + d_h^R

Main tradeoff Full per-head K/V capacity Smallest cache, weakest head diversity Group-level sharing Small cache plus head-specific reconstruction

So MLA is not smaller than pure MQA. MQA still has the smallest raw cache. MLA's advantage is that it compresses KV cache to roughly a tiny-GQA size while retaining much stronger head-specific expressiveness. DeepSeek reports in its ablations that MLA outperforms its MHA baseline while using a fraction of the KV cache.

Why this matters for serving

For LLM inference, the KV cache is often the bottleneck for:

  1. Batch size: how many concurrent requests you can serve.
  2. Context length: how long a single request can be.
  3. Decoding speed: how fast tokens can be generated when HBM reads dominate.

MLA reduces KV-cache pressure by about 57x versus standard MHA in the DeepSeek-V2 configuration, which can improve all three: larger batches, longer contexts, and lower decode-time HBM traffic. The realized serving gain still depends on the full system: MoE routing, kernels, quantization, batching, hardware, and memory layout.

This is why MLA matters for serving efficiency: it is an architecture-level change that attacks KV-cache memory directly while preserving model quality in DeepSeek's reported ablations.
