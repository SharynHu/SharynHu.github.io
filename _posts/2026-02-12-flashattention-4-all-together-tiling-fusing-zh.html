这一篇把前面的概念合起来：tiling、fusing、online softmax，以及反向传播中的重计算。

前向传播

FlashAttention 把 \(Q,K,V\) 切成 block。每次把一个 query block 和若干 key/value block 搬到 SRAM/shared memory 中计算。

对每个 query block，算法维护：

  • 当前最大值 \(m_i\)。
  • 当前归一化因子 \(\ell_i\)。
  • 当前累积输出 \(O_i\)。

Fusing：为什么更省内存

标准实现会把 score、softmax probability 等中间结果写回 HBM。FlashAttention 把这些操作融合在一个 kernel 的 block 内部，尽量只把最终输出写回 HBM。

也就是说，它不是先完整生成 attention matrix，再对它做 softmax，再乘 \(V\)；而是边算边归一化，边累积输出。

反向传播：重计算

反向传播需要 attention probabilities。如果前向没有保存完整矩阵，反向怎么办？FlashAttention 的答案是：重新计算需要的 block。

这看起来增加了 FLOPs，但通常是值得的，因为 GPU 计算相对便宜，HBM 读写相对昂贵。

简化版伪代码

for q_block in Q:
    m = -inf
    l = 0
    o = 0
    for k_block, v_block in zip(K_blocks, V_blocks):
        scores = q_block @ k_block.T / sqrt(d)
        m_new = max(m, rowmax(scores))
        p = exp(scores - m_new)
        l_new = exp(m - m_new) * l + rowsum(p)
        o = exp(m - m_new) * o + p @ v_block
        m, l = m_new, l_new
    output = o / l
